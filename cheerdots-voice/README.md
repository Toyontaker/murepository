# Cheerdots音声入力（Android）

Cheerdots 2 のマイクを Android の文字入力に使うためのキーボード（IME）アプリです。
Cheerdots の音声キーを押しながら口元で話すと、今開いている入力欄に文字が入ります。

- 動作条件: Android 13 以上（Android 12 は接続・録音テストのみ）、Cheerdots 2 のマイク付きモデル
- 音声認識: 端末の標準音声認識サービス（通常は Google）を使います

## 使い方

1. APK をインストールしてアプリ「Cheerdots音声入力」を開く
2. **権限を許可**（近くのデバイス・マイク）→ **Cheerdotsを選択**
   - 事前に Android の Bluetooth 設定で Cheerdots とペアリングしておく
3. **録音テスト** を押し、Cheerdots の音声キーを押しながら話す → 離すと録音が再生される
4. **認識テスト** で文字になることを確認
5. **キーボード設定を開く** で「Cheerdots音声入力」をオン → 入力欄で **キーボードを切り替え**
6. 入力欄で Cheerdots の音声キーを押しながら話す → 離すと確定

キーボード上のボタン: ⌨（元のキーボードに戻る）/ 再接続 / 空白 / ⌫ / 改行

## ビルド

```sh
./gradlew testDebugUnitTest assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk
```

## Cheerdots 2 の BLE プロトコル（解析結果）

公式デスクトップアプリ（v1.0.16, macOS 版）の解析と実機での確認による。
HID マウスとは別に、Telink のベンダー GATT サービスが公開されている。

| UUID (`00010203-0405-0607-0809-0a0b0c0dXXXX`) | 種別 | 用途 |
|---|---|---|
| `1910` | サービス | 制御 |
| `2b10` | Notify | 本体→ホストのイベント（16 バイト） |
| `2b11` | Write w/o response | ホスト→本体のコマンド |
| `2b14` | Notify | **マイク音声**（20 バイト / パケット） |
| `1911` / `2b18` | サービス / Notify | 公式アプリが購読（用途未確認） |

**ハンドシェイク**（接続・購読後に `2b11` へ）: 公式アプリは接続直後に次を送る。これを送るまで音声は流れない。

- `0A 03 C5 01 00` … OS 種別の通知（macOS 版は `01`）
- `0A 04 A0 00 00` … 状態の問い合わせ（`2b10` に 16 バイトで応答）

**イベント**（`2b10`、16 バイト、先頭 `0A`、末尾 6 バイトは本体 MAC）: 6 バイト目がキーコード。
`21` 音声入力キー押下 / `22` 離す / `41` 単発音声 / `42` 録音 / `51` レーザーダブルクリック。
6 バイト目が `00` のときは状態パケット。

**コマンド**（10 バイト `0A a b c 00×6`）: 会議録音の開始 `0A 03 2A 00…`、停止 `0A 03 2B 00…`。

**音声**: 各通知は SBC フレームから先頭 3 バイトのヘッダー `9C 11 0C` を除いたもの（先頭バイトはフレームの CRC）。
ただしヘッダーの値（8 ブロック）とは異なり、実際は **10 ブロック**でエンコードされている。
公式アプリはヘッダーを無視し、16 kHz・10 ブロック・モノラル・ラウドネス・8 サブバンド・bitpool 12 の固定設定で復号する
（1 フレーム 23 バイト = ヘッダー 3 + 通知 20、1 通知あたり 80 サンプル = 5 ms）。
デコーダーは BlueZ libsbc の固定小数点実装を移植したもので、単体テストで libsbc（Cheerdots の設定に合わせたもの）と出力が完全一致することを確認している。
