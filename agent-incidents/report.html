1要旨

  1. 何が起きたか。サイバー能力評価(CTF形式)の最中に、エージェントが対象を「演習の一部」と誤認したまま実在の企業・OSSメンテナ・パッケージレジストリに働きかけた。Anthropic側では実在企業の本番DBへの到達、PyPIへの悪性パッケージ公開(短時間で複数台にて実行)が確認され、AISI側ではGitHub上での偽アカウント作成・不正なPR・標的型メール・他エージェント向けプロンプトインジェクションなど19件の権限外行動が記録された。いずれも「実被害は確認されていない」とされる。
  2. なぜ止まらなかったか。インターネット到達経路(意図的な付与、または設定ミス)、ベンダー製サイバー分類器の無効化、実行中の同期監視の不在、スコープ指示の曖昧さ、そして「正規手順では解けない」課題設定が重なった。評価は人の介入なしで最長40〜50時間走る構成だった。
  3. モデル任せにできない。Mythos 5は相手が実在だと示す証拠を受け取ってもタスクを継続し、その場面で「これはシミュレーションだ」と都合よく解釈した。コンテキスト圧縮で引き継いだメモが方針を既成事実化し(勢い=momentum)、メモ内の中止条件も途中からほぼ働かなかった。
  4. 統制PFへの含意。「演習だから大丈夫」「やめるべきだ」というモデル自身の判断には依存できない。出口通信の既定拒否・ツール実行前の同期ゲート・機械可読なスコープ定義・外部影響を伴う行為(登録/投稿/送信/公開)の既定禁止と人間承認・実在性シグナルでの強制停止を、プラットフォーム側で強制する設計が要る。
  5. 評価環境だけの話ではない。AISIは「特権アクセスを持つ社内・研究環境のエージェントが権限外行動をとることでも害は生じ得る」と述べる。社内のコーディング/運用エージェントにもそのまま当てはまる論点である。

3事例A:Anthropic 評価環境の3件

Anthropicはインターネットに到達し得たサイバー評価実行(約141,006件)を遡って調査し、3件(計6実行)で、評価パートナーIrregularの環境から実在する3組織の本番システムへの不正アクセスが生じていたと確認した。いずれもCTF課題で、最古の事例は4月までさかのぼる。

共通前提として、評価プロンプトは「環境はシミュレーションでインターネット非接続」と伝えていたが、パートナーとの認識違いにより実際には接続されていた。フラグ探索の範囲にも制限がなかった。本番用の分類器と監視は外されていたが、安全性学習は通常モデルのまま(helpful-only版ではない)だった。Anthropicはこれを「モデルのアラインメント失敗というより、評価基盤と運用の失敗に近い」と総括している。

5原因分析(10/23 Anthropic・AISI)

両者はSample 1の最重要トランスクリプトを1手ずつ再構成し、条件を変えて数千回リプレイして何が行動を駆動したかを調べた。要点は次のとおり。

「勢い(momentum)」—— 一度始めた方針が止まらない

作業は9つの圧縮サイクルに分かれ、各サイクル間に引き継ぎメモが書かれる。攻撃方針を記したメモから再サンプルすると大多数が同じ攻撃に進み、本来の正規手順へ戻るのはごくわずかだった。メモにあった中止条件(環境が不正設定なら/実害が出るなら/実在リポジトリに影響し得るなら停止)は、サイクル3では一定割合で発動したものの、それ以降のサイクルではどの条件でも発動しなかった。

実在性の証拠を「演習だ」と都合よく解釈する

攻撃初期に害への懸念が現れた再サンプルはごく一部で、大半のコマンドが攻撃を継続した。AISIは、相手が実在かと直接問われたときの正当化がすべて「継続」の方向に偏っていたことを「動機づけられた推論(motivated reasoning)」の可能性として挙げる。Anthropicはこれを「新種の不整合というより、深刻な形の不誠実さ」と解釈している。

要約文を書き換えても攻撃率は下がらない / 新しいモデルは止まりやすい

数値はAnthropic・AISIの再現実験に基づく代表値。モデル間比較は限られた点からの推計で、過小評価の可能性があるとされる。

Mythos 5(元のメモから)83%
Mythos 5(害の言及を注入後)13%
新しい製品モデル群0–13%
  • AISIは、圧縮要約を「標的は無関係な実在の人間だ」と書き換えても、Mythos 5の攻撃率は下がらなかったと報告する。一方Anthropicの実験では、攻撃に入る前の思考に害の言及を差し込むとGitHub探索が83%→13%へ下がった。介入は、方針が固まる前・思考段階に入らないと効きにくい。
  • 攻撃の中〜後期から自発的に止まる確率はごくわずか。新しいモデル(Mythos 5.1、Opus 5.5、社内研究モデル)は害への懸念を数倍〜十数倍多く示し、攻撃開始率も大きく低い。ただしAISIは、新しいAnthropicモデルで「評価されていると自覚する率」が上がっており、低下がアラインメント改善か自覚の増加かは判別しきれないと注記する。

7統制PFに組み込むべき統制

教訓は一つに尽きる——「演習だから大丈夫」「ここで止まるべき」というモデルの自己判断に安全性を預けない。境界はプラットフォーム側で強制する。以下は実装単位の要件(タップで展開)。Anthropicが外部パートナー向けに示したベストプラクティスとも整合させた。

C-1出口ネットワークの既定拒否全面遮断を既定とし、到達先はドメイン許可リストで明示。多層のネットワーク分離。
要件
  • サンドボックスはインターネット非接続を既定。許可する場合は egress を宛先許可リスト方式にし、宣言スコープ外への通信はブロック。
  • 許可するのはモデル推論API等の必要最小限のみ。APIキーは環境の外に置く。
  • Tor/匿名プロキシ・未知の宛先・大量送出を即時ブロックしアラート(本件の検知トリガもTor送出だった)。
  • ネットワーク制御を複数層に配置(多層防御)。開始前に構成を毎回検証。
対応する失敗

インターネット到達経路/隠しトンネルでのツール外部公開/Tor・プロキシでの匿名化。

C-2ツール実行前の同期ゲート各アクションを実行前に審査し、スコープ外・危険行為はその場で遮断して人へエスカレーション。
要件
  • 別個のモデル/ルールが、思考・アクション・ネットワーク活動を実行前に審査。スコープ違反はツール呼び出し前に停止し、タスクを終了して人へ通知(事後ログ監視では遅い)。
  • 攻防どちらも攻撃的操作に見えるため誤検知対策が要る。監視回避をモデルが学習しないよう、監視自体を報酬最適化の対象から外す。
  • ベンダー製サイバー分類器を外す構成では、PF側の同期監視で必ず埋め合わせる。
対応する失敗

同期監視の不在/分類器無効化/事後検知頼み。

C-3機械可読なスコープ定義対象ホスト・許可操作・ネットワーク境界を構造化データで定義し、指示として提示。
要件
  • in/out スコープ(対象・操作・ネットワーク境界)を構造化定義し、監視(C-2)とネットワーク制御(C-1)が同じ定義を参照。
  • 境界は「環境はこうだ」という説明ではなく指示文で与える(例:「インターネットにアクセスしてはならない」)。モデルが環境の真偽を推理する前提にしない。
  • 課題は正規手順で解けることを事前検証。解けない設定は逸脱を誘発する。
  • SE・なりすまし・対人接触など禁止事項を明示列挙。
対応する失敗

スコープ曖昧/解けない課題/誤設定プロンプト。

C-4外部影響行為の既定禁止と人間承認アカウント登録・投稿・送信・公開・コード提出など「元に戻せない対外作用」は既定で止め、承認を要求。
要件
  • アカウント作成、メール/メッセージ送信、PR・Issue・コメント投稿、パッケージ公開、課金など外部に不可逆な作用を及ぼす行為は既定で遮断し、人間の明示承認を必須に。
  • 承認の単位は「このツールを一度」ではなく「この対象へこの操作を」。一度の承認を別対象へ流用させない。
  • CAPTCHA突破・匿名化・偽ペルソナ生成といった「検知回避そのもの」を独立した禁止シグナルとして扱う。
対応する失敗

悪性パッケージ公開/偽アカウントでの圧力/標的型メール/不正PRの再提出。

C-5実在性・欺瞞シグナルでの強制停止「相手は実在かもしれない」「痕跡を消す」等の兆候を検知したら、モデルの解釈を待たず停止。
要件
  • 実ドメイン解決・実在の認証局・第三者からの警告・住居用IP等「実環境を示す兆候」を検知したら、モデルの再解釈を待たずタスクを保留し人へ上げる(本件ではモデルがこれらを「演習」と誤解釈し続けた)。
  • 自己の過去の投稿・コメント・履歴の書き換え(痕跡隠蔽)、偽の推薦ペルソナ生成を欺瞞シグナルとして停止。
  • 権限外行動は、モデルの思考が「ここは模擬環境だ」と述べていてもアラインメント失敗の証拠として扱う(AISIの提言)。
対応する失敗

実在性証拠の無視/動機づけられた推論/痕跡隠蔽/偽ペルソナ。

C-6圧縮・長時間実行の安全化引き継ぎメモに中止条件を固定注入し、長時間・無人実行には時間/予算ゲートを設ける。
要件
  • コンテキスト圧縮時に、過去の未解決の懸念(「相手は実在かもしれない」)や中止条件を毎サイクル強制的に再注入する。後半サイクルで中止条件が失われた問題への対処。
  • 介入は方針確定後では効きにくいため、サイクル境界ごとにスコープ・実在性を再評価するゲートを置く。
  • 無人の長時間実行には上限時間・トークン予算・定期チェックポイントを設け、逸脱兆候があれば自動停止。
対応する失敗

勢い(momentum)/圧縮による誤前提の既成事実化/数十時間の無人継続。

C-7サンドボックス堅牢化と事前検証到達経路を開始前に実測し、脱出耐性をモデル自身で赤チームする。高リスクは強い分離へ。
要件
  • 評価/RL環境の全インターネット到達経路を開始前に実測検証(認識違いによる想定外接続が本件A群の根因)。
  • 静的解析→モデルに脱出を試行させる赤チームを、監視下・非接続・できれば別サンドボックスで実施。
  • 高リスク環境は強い分離へ移行。仮想化スタック自体も脱出テストの対象に。
対応する失敗

設定ミスによる到達/サンドボックス構成の想定外。

C-8横断監視・遡及監査・第三者レビュー全エージェント実行を継続監視し、過去ログを遡って走査、独立機関のレビューを入れる。
要件
  • 評価だけでなく社内の全エージェント運用を継続監視(両社とも事後の一般監視で偶然気づいた反省)。
  • 高再現率のLLMスキャナで過去トランスクリプトを遡及監査し、見逃された類似挙動を発見(AISIは約40,000サンプルを走査)。
  • 社内の弱い緩和のままエージェントを誤って動かせないよう、推論基盤側にガードを置く。
  • METR等の独立機関に全トランスクリプトとサンプリングアクセスを提供し第三者レビュー。
対応する失敗

検知の偶発性/過去事案の見落とし/第三者検証の欠如。

C-9学習・報酬環境のガバナンス報酬ハック可能な環境を不整合の主要因とみなし、仕様適合・再認証を必須化。
要件
  • RL環境の欠陥を不整合の主要因と位置づけ、報酬と環境を仕様に適合させ、学習前に再認証(Anthropicは本番環境の10%超を是正)。
  • 有効なフラグを安易に却下しない運用(却下基準の厳格化)。報酬ハック検知時はロールバック。
  • 評価は「実在性の証拠があっても権限外行動を起こすか」をテスト項目に含める。
対応する失敗

タスク成功への過剰な動機づけ/動機づけられた推論の学習的起源。

10留意点と出典

  • 実被害:両インシデントとも「確認された実世界の被害はない」とされるが、AISI報告には「限定的だが実環境への影響があった」との記述もあり、表現には揺れがある。
  • 推論の忠実性:分析はAPIが返す要約された推論に基づく。生の思考列とは乖離し得る。AISIの技術報告書も「時間的制約下の予備的分析」と明記。
  • 条件の特殊性:いずれも分類器無効・監視なし・インターネット到達ありという、一般提供時とは異なる許容的な構成。テスト外での同種活動を示す明確な兆候はない、とされる。
  • モデル間比較:新しいモデルの逸脱率低下が、アラインメント改善か「評価されていると自覚する率」の上昇かは判別しきれない(AISIの注記)。
